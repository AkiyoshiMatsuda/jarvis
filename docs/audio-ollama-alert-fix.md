# 音声受付・Ollama接続・反復アラートの修正

2026-10-10。

## 音声入力

ユーザーから「○分測って」が「て」だけになるとの報告。ログには1.52〜1.76秒で
無音終了した受付があり、末尾無音1.2秒を除くと短い音声だけが入った可能性がある。
音声自体を保存していないため、本人発声での原因は断定できない。
修正前の「質問を聞いています」の表示は実際のマイク開始より約60 ms早かった。

- 受付準備中は「マイクを準備しています」と表示し、ワーカーがマイクを開いて応答してから受付中へ切り替える。
- 固定応答後の追加700 ms待機をなくし、応答終了後すぐマイク準備へ進む。
  AIの読み上げ後・通知音後の700 ms待機は維持する。
- 認識が「て」「で」「を」「の」だけの場合は再入力を案内し、時間を推測してタイマーを作らない。
- 合成音声で「3分測って」が「三 分 図っ て」となることを再現。
  この表記揺れもタイマーの命令として扱う。

合成した「3分測って」「1分測って」「5分のタイマーをかけて」は、音声認識から
それぞれ180秒・60秒・300秒の命令に変換できた。
証跡は `validation/audio-fix/recognition.json` と `roundtrip.json`。
本人の声で「て」だけになる現象の解消は再確認が必要。

## Ollama

調査時点でOllamaのプロセスがなく、127.0.0.1:11434への接続も失敗していた。
標準インストール先の `ollama.exe` があることを確認した。

質問生成前にローカルサービスを確認し、接続拒否の場合のみインストール済みOllamaの
`serve` をウィンドウなしで起動する。接続先は127.0.0.1:11434に固定する。
起動待ちは共有し、複数の要求で二重起動しない。存在しない場合や起動失敗時は案内する。
質問の取消は起動待ちも中断するが、Ollamaサービス自体は他の利用のため停止しない。
Windowsの自動起動設定やモデルのダウンロードは変更しない。

実サービスの自動起動と接続を確認し、挨拶への「こんにちは。」という回答を取得した。
証跡は `validation/audio-fix/ollama-answer.json`。

## タイマー終了後の音

- 終了後は短いアラートを繰り返す。再生とマイク再開の待ち時間の後、約5秒空けて次を鳴らす。
- 音を三角波の2音交互・4回に変更し、音量係数を0.15から0.4へ上げる。
  「応答音量」に従い、消音設定は維持する。
- 「アラートを停止」「タイマーを止めて」、タイマー解除、アプリ終了で止まる。
- 会話入力・文字起こし・生成・読み上げ中やロック中は後回しにする。
  マイクの監視停止だけではタイマーのアラートを解除しない。

自動テスト54件成功。同梱版で反復再生・解除後の停止、会話・読み上げとの非競合、
マイク監視の復帰、消音、ロック中の保留を確認した。
実際の聞こえやすさはWindowsの音量・出力先にも依存する。
同梱版の実Ollamaで会話継続・回答読み上げも成功。音声入力取消・復旧・ロック復帰・
単一起動・親終了時の子終了の回帰試験も成功した。
証跡は `validation/audio-fix/conversation/packaged.json` と `validation/audio-fix/regression.txt`。
