# 予定の事前通知と画面整理

## 使用方法

JARVISの右上「設定」→「カレンダー・通知」を開きます。Googleに接続済みであることを確認し、「予定の開始前に通知する」をオンにしてください。5・10・15・30・60分前から選べます。初期状態はオフ、選択時間は10分です。既存のGoogle接続・Ichiroなどの音声設定は引き継ぎます。

通知時にはホーム・設定のどちらにも予定カードを表示し、ウィンドウをフォーカスを奪わず表示してタスクバーを点滅させます。Windowsにも通知します。Windows通知には予定名を出しません。「閉じる」でカードを消せます。音声入力と競合しないよう、通知音・自動読み上げは行いません。

メインカレンダーの時刻付き予定のみが対象です。終日・キャンセル・辞退・開始済みの予定は通知しません。繰り返し予定は各回を扱います。Googleの予定やGoogle側の通知設定は変更しません。

## タイミングと制限

- JARVISが起動している間、約1分ごとに今後24時間の予定を取得します。そのため指定時刻から最大約1分＋通信時間のずれが生じます。
- 質問・回答・読み上げ・タイマー通知中は事前通知の表示を待機します。開始前に待機状態へ戻った場合に通知し、開始後になった予定は通知しません。タイマーのカウントはそのまま継続します。
- ロック・スリープ中は取得と通知を停止し、復帰後に再取得します。終了中やオフライン中の通知は保証できません。スリープ解除やPC起動を行う機能ではありません。
- 削除・時刻変更は次の取得で反映します。通信エラー時は古い一覧から通知せず、画面に案内して約1分ごとに再試行します。
- 同じ予定ID・開始時刻は一度だけ通知します。通知時間の変更やアプリ再起動でも再通知しません。開始時刻が変更された予定は再度対象になります。
- 通知済み記録は予定IDと開始時刻のハッシュ、および期限のみを `%APPDATA%\jarvis-local\reminder-seen.json` に保存します。予定名・本文は保存せず、会話履歴・Ollama・診断ログにも渡しません。このファイルはGitの除外対象です。記録を削除・破損すると重複通知の可能性があります。
- Windows側の通知設定によりトーストが表示されなくても、JARVIS内のカードで確認できます。

取得には既存の読み取り専用権限を使います。取得範囲・繰り返し展開・ページングは [Google Calendar Events.list仕様](https://developers.google.com/workspace/calendar/api/v3/reference/events/list) に従います。

## 画面の変更

- ホーム：状態、文字入力、よく使う質問、回答。タイマーと会話履歴は存在する場合だけ表示。
- 設定：音声・起動／カレンダー・通知／天気の3分類。
- 文字入力：Ctrl＋Enterで送信。日本語変換中は送信しません。
- 設定中も予定通知・エラーを表示し、タイマーや処理がある場合はホームへの案内を表示。
- 地域検索などのエラーに、無関係な音声ワーカー再起動ボタンを出さないよう整理。

## 検証

単体・回帰83件成功。事前通知の対象除外、同時刻の複数予定、更新・削除、重複防止と再起動、通信失敗、通知記録の保存失敗、ロック・無効化・切断時の中止を含みます。同梱版の分離設定と合成予定で、設定画面遷移・保存、通知カード、閉じる、タイマー継続、ログ・履歴に予定名が残らないことを確認しました。

実際のGoogleアカウントの予定による時刻到達通知とWindowsトースト表示は未検証です。確認する場合はGoogle側で数分先の時刻付き予定を用意し、通知を5分前に設定してJARVISを待機させてください。

```bat
cd /d D:\Jarvis
npm test
.venv\Scripts\python.exe tests\check_reminder_packaged.py
```
