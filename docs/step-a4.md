# Step A-4 — AI回答のローカル読み上げ

実装日: 2026-10-09。文字入力・音声入力のAI回答を、日本語音声で読み上げる。
本人の発声による質問入力の評価は、引き続きユーザーが可能なタイミングで行う。

## 試し方（cmd、マイク不要）

```bat
cd /d D:\Jarvis
start-jarvis.cmd
```

1. 「AIの回答を読み上げる」がオンで、「応答音量」が消音でないことを確認する。
2. マイク監視を停止したまま「文字で質問する」に「こんにちは。短く挨拶してください。」と入力する。
3. 「質問する」を押すと、AI回答が表示され、その回答を読み上げる。
4. 長い回答の途中では「読み上げを停止」で音声だけを止められる。質問・回答は残る。
5. チェックをオフにすると文字表示のみになり、アプリ再起動後にも引き継がれる。

Ollamaへの接続エラーは従来どおり、スタートメニューからOllamaを起動して再試行する。
読み上げに失敗した場合も回答は文字で確認できる。
日本語音声がないPCでは、Windows「設定」の「時刻と言語」から日本語の言語オプションを開き、
音声合成の機能を追加してJARVISを再起動する（Windowsの版によって表示名は異なる）。
音が聞こえない場合はWindowsの出力先・音量ミキサーとJARVISの応答音量も確認する。

## 実装範囲

- ElectronのWeb Speech APIを使い、`localService === true` の日本語音声を明示選択する。
  該当する音声がなければエラーとして文字表示に戻す。リモート音声への切り替えは行わない。
- AI回答の文字列をPC内の音声合成に渡す。音声ファイルや回答文をディスクに保存しない。
- 回答生成→表示→読み上げ→700 ms待機→元の監視設定へ戻る。
  文字入力時に監視が停止していた場合、その後も停止を維持する。
- 「読み上げを停止」、読み上げ設定をオフ、監視停止、取消、ロック、スリープ、終了で再生を中断する。
  ロック・スリープでは質問・回答も消去する。古い再生イベントは無視する。
- 音声一覧の取得待ちは3秒、読み上げ全体は180秒で打ち切る。失敗時にも回答文を残す。
- 消音時は読み上げ処理を省略する。「応答音量」は次の音声に適用される。
- 旧設定ファイルは読み上げオンとして移行する。固定の「はい、何でしょう？」の音声は従来どおり。
- 会話履歴の継続、Web検索、PC操作は今回の範囲に含めない。

## 検証

自動テスト34件成功。ローカル日本語音声の選択、リモート音声の拒否、遅延した音声一覧、取消後のイベント無視、設定移行を含む。
同梱版で実際の音声合成の開始・終了イベント、途中停止、消音、設定保存、ロック時停止、AI回答との接続を確認した。
このPCではローカル日本語音声としてAyumi、Haruka、Ichiro、Sayakaを取得でき、先頭のAyumiを選択した。
日本語の計算質問に対するAI回答「5です。」の表示と読み上げ完了を確認し、マイク監視は停止を維持した。
証跡は `validation/step-a4/packaged.json`、`preview.png` に保存した。
既存機能の同梱版回帰試験も成功。マイク開始・停止・再起動、質問入力取消、ワーカー異常時の復旧、
ロック・復帰イベント、二重起動防止、親終了時の子終了を確認した。結果は `validation/step-a4/regression.txt`。
人が耳で聞く発音・音質・聞き取りやすさ、本人発声からの一連の動作、長時間の読み上げ耐久試験は未評価。
