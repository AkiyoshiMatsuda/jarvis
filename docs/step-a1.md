# Step A-1 — 呼びかけ後の質問入力

実装日: 2026-10-09。

「Hey Jarvis」→固定の返事→700 msの抑止→「質問を聞いています」→入力終了→待機。
「質問入力を開始」ボタンでも同じ流れを開始できる。文字起こしとAI回答はまだ行わない。

- 発話なし約5秒、発話後の無音約1.2秒、最長約15秒で終了。
- 16 kHz・モノラル・int16の入力をメモリに一時保持する。上限は約480 kB。
- 今回は終了時に音声を破棄し、ファイル保存・ネット送信を行わない。
- 発話の暫定判定はRMS 0.012以上が240 ms継続した場合。音量に基づく判定であり、
  人の声と環境音の区別はできない。本人発声での閾値調整は未実施。
- 入力中のウェイクワード推論は行わない。終了後は履歴をリセットして再開。
- 「入力を取り消す」は音声と入力を中断し待機へ戻る。「監視を停止」はマイクを解放し停止を維持。
- ロック・スリープ・終了・ワーカー障害でも入力を破棄する。
- データ欠落時は部分入力を破棄。入力が3秒途絶した場合は既存の障害復旧へ移る。
- Electron側でも20秒の終了通知待ち上限を設け、ワーカーが応答しなければ復旧する。

## 自動起動の修正

旧実装はカスタム名 `JARVIS Local` で登録していたが、既定のAppUserModelIdを参照する
`openAtLogin` で確認したため、登録できても失敗と判定して元に戻していた。
`launchItems` の名前・実行ファイル・ユーザースコープ・有効状態で確認するよう変更した。
`launchItems.args` は `--login-start` のようなスイッチを返さないため照合には使用しない。
自動起動設定の失敗が、音声監視の状態をERRORに変えてしまう問題も修正。

参考: [Electron API](https://www.electronjs.org/docs/latest/api/app#appgetloginitemsettingsoptions)、
[Windows実装](https://github.com/electron/electron/blob/main/shell/browser/browser_win.cc)。

### 更新後の操作（cmd）

```bat
cd /d D:\Jarvis
start-jarvis.cmd
```

アプリの「Windowsログイン時に自動起動」にチェックを入れ直す。
Windowsの「設定 → アプリ → スタートアップ」で `JARVIS Local` が有効になっているか確認する。
アプリを終了して開き直してもチェックが維持されることを確認できる。
実際のログイン起動は次回のログイン時に確認する（この作業で再ログインは行わない）。
起動後に監視させるには監視も開始してから終了する。監視停止の設定ならログイン後も停止する。
実行ファイルを移動した場合は移動前に自動起動をオフ、移動後にオンにし直す。

声を出せるようになったら「質問を聞いています」の表示後に話し、無音で待機へ戻るか確認する。
発声できなくても「質問入力を開始」と「入力を取り消す」のボタン操作は確認できる。
周辺に音がある場合、発話なしでも最長約15秒まで入力が続く場合がある。
