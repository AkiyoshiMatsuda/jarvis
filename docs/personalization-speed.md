# パーソナライズと高速化（2026-10-11）

## 使い方

同梱版を起動すると、初期設定では自動記憶とAIモデル保持が有効です。「設定 → 記憶・高速化」で変更できます。Ichiroなどの既存設定は引き継ぎます。

普通のローカルAIとの会話後、5秒以上待機すると、Ollamaがユーザー本人の発言から好み・興味・学習中のことなどを選びます。会話全体を保存する方式やモデルの再学習ではなく、選んだ記憶を次回のローカル回答に参考情報として渡す方式です。

例：「私はマンゴーが好きです」「回答は短めが好みです」。記憶整理が終わった後に「新しい会話」を押しても、保存済みの好みは残ります。

- 「回答は短めが好き、覚えて」：明示的に保存します。240文字以内です。
- 「マンゴーを忘れて」：記憶本文に指定語を含む記憶を削除します。一致しなければ設定一覧から削除できます。
- 「記憶をすべて忘れて」：保存した記憶をすべて削除します。
- 設定では内容の修正、再有効化、個別削除、全削除ができます。削除・修正時は短期会話履歴も消去します。

自動記憶をオフにすると、記憶の抽出と回答への利用の両方を止めます。保存済み情報自体は残るので、消したい場合は削除を使ってください。

## 記憶の選択と制限

Ollamaが最大2件の追加と、矛盾する既存記憶の無効化を提案します。追加内容は今回のユーザー発言からの正確な抜粋であることをJARVIS側で検査し、推測・言い換えは保存しません。既存情報は自動で完全削除せず「自動整理で無効化」として一覧に残します。

期限は1・30・180日からOllamaが選びます。期限切れの記憶は回答に使いませんが、一覧には残して再有効化・削除できるようにします。明示保存・手動修正は180日です。全体の上限は100件、1件240文字です。上限に達した場合は不要な記憶を削除してください。回答には有効な記憶から最大8件・合計1,200文字までを渡し、現在の質問を優先します。

自動分類の精度には限界があります。引用や仮定を本人の好みと誤解する可能性もあるため、一覧を確認・訂正できます。キーワードなどで秘密情報を除外しますが、全ての秘密情報を検出できるものではありません。

保存先は `%APPDATA%\jarvis-local\personal-memory.enc`。WindowsのsafeStorageで暗号化し、Gitの除外対象です。記憶本文は診断ログに書きません。読み取れない記憶ファイルは自動処理で上書きせず、全削除による初期化を案内します。

カレンダー、天気、Web検索の結果、AI自身の回答は記憶の抽出に使いません。長期記憶を検索サービスにも付け加えません。記憶整理はPC内のGGUFモデルで行い、新しい入力・回答・タイマー通知・ロック・終了を優先して中断します。中断された整理は保存せず、次の会話で得た情報を優先します。

## 高速化

1. **Ollamaのモデル保持**：従来の `keep_alive: 0` から、標準で10分間保持する方式に変更しました。回答・検索結果の抽出・記憶整理で設定を揃えます。設定をオフにした場合は次の処理終了時にモデルを解放します。
2. **回答の逐次表示**：全文の完成前に受信した文字を画面へ表示します。生成中であることを示し、確定前の文章は会話履歴に保存しません。日本語補正が入る場合は表示が置き換わります。読み上げは補正を終えた全文の確定後です。
3. **文字起こしモデルの再利用**：Voskモデルとハッシュ検証を発話ごとにやり直さず、専用の子プロセスで再利用します。認識器は発話ごとに新しくし、PCMは処理後に解放します。音声をファイルに保存しません。未使用10分・親の終了で子も終了し、認識途中のキャンセル・時間切れでも終了します。次回は新しく読み込みます。

AIと文字起こしのモデル保持にRAM・VRAMを使用します。文字起こしの保持はAI高速応答のチェックとは独立です。初回・10分以上の未使用後・認識キャンセル後は読み込み待ちが発生します。音声入力の無音判定や日本語モデルは変更していません。

[Ollama Chat APIの仕様](https://docs.ollama.com/api/chat) に従い、ストリーミング、保持時間、応答のロード・生成時間を扱っています。回答画面の「最初の文字受信」はJARVISが最初の文字を受信するまでの時間で、実際の画面描画や音声の開始時刻ではありません。
