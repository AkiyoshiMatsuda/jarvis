# Googleカレンダー連携の設定と使い方

実装日: 2026-10-10

JARVISの画面に「Googleカレンダー」を追加しました。初回のみ、以下のGoogle側の設定と接続が必要です。
実装と合成データでの検証は完了していますが、本人のGoogleアカウントへの接続・実予定の照合は未確認です。

## 1. Google側の認証設定を作る

1. [Google Cloud Console](https://console.cloud.google.com/) に、予定を確認したいGoogleアカウントでログインします。JARVIS用のプロジェクトを作成、または選択します。
2. 「APIとサービス」→「ライブラリ」で **Google Calendar API** を検索し、有効にします。
3. 「Google Auth Platform」から初期設定を進め、アプリ名を `JARVIS`、サポート・連絡先メールを自分のメールにします。個人のGoogleアカウントでは対象を「外部」にします。
4. 「対象／Audience」のテストユーザーに、予定を取得する自分のメールアドレスを追加します。「データアクセス」でスコープを追加する場合は `https://www.googleapis.com/auth/calendar.events.readonly` を選びます。
5. 「クライアント」→「クライアントを作成」で、アプリケーションの種類を **デスクトップアプリ** にします。名前は `JARVIS Desktop` などで構いません。Webアプリやサービスアカウントではありません。
6. 作成したクライアントのJSONをダウンロードします。保存場所は「ダウンロード」フォルダーのままで構いません。

画面の表記はGoogle側の更新で変わる場合があります。API有効化とデスクトップクライアント作成の根拠は [Google公式セットアップ](https://developers.google.com/workspace/calendar/api/quickstart/python) です。この資料のPythonコードや追加ライブラリを実行する必要はありません。

## 2. JARVISで接続する

cmdで次の順に実行します。

```bat
cd /d D:\Jarvis
start-jarvis.cmd
```

1. JARVISの画面を下へスクロールして「Googleカレンダー」を開きます。
2. 「認証設定JSONを読み込む」で、先ほどダウンロードしたJSONを選びます。
3. 「Googleに接続」を押します。
4. 開いたブラウザーでGoogleアカウントを選び、カレンダーの予定を読み取る権限を許可します。
5. JARVISに戻って「接続済み」を確認します。

パスワードはGoogleの画面で入力します。JSONや認証コードをこのチャットへ貼り付ける必要はありません。
接続待ちは3分で終了し、画面の「接続を取り消す」でも中断できます。

## 3. 予定を聞く

文字入力で先に試せます。接続後は音声でも同じ処理を使います。

- 「今日の予定」
- 「明日の予定を教えて」
- 「今週の予定を教えてください」
- 「今日のスケジュールは？」

2026-10-10に次の言い方も追加しました。語間に空白がある音声認識結果や、全角数字・漢数字の日付にも対応します。

| 確認したい範囲 | 入力例 |
| --- | --- |
| 翌々日・前日 | 明後日の予定、昨日の予定 |
| 週単位 | 来週の予定、再来週の予定、先週の予定 |
| 月単位 | 今月の予定、来月の予定、再来月の予定、先月の予定 |
| 週末 | 今週末の予定、来週末の予定 |
| 曜日 | 来週の月曜日の予定、今週の金曜日の予定、日曜日の予定 |
| 日付 | 10月15日の予定、十月十五日の予定、2027年1月1日の予定、10/15の予定 |
| 日数 | 3日後の予定、今後7日間の予定 |
| 次の予定 | 次の予定はいつ、次の予定を教えて、直近の予定 |

「予定」の代わりに「スケジュール」でも使えます。「教えて」「見せて」「確認したい」「ある？」「は何？」などの問いかけにも対応しています。

月の範囲は1日〜月末、週末は該当週の土曜・日曜です。年を省略した日付は **今年** の指定として扱い、過ぎていても来年へ繰り越しません。
曜日だけの指定は今日を含む次の該当日です。「今週の金曜日」は既に過ぎていても今週を検索します。
「今後7日間」は今日0時から7日分、日数指定の上限は365日です。存在しない日付や範囲外の日数はエラーにし、AIへ推測を依頼しません。

「次の予定」は **今後365日以内に開始する、最も近い予定** です。進行中の予定は対象外で、同じ開始日時の予定が複数ある場合はまとめて案内します。
終日予定の開始はその日の日本時間0時として扱うため、今日の終日予定は開始後なら対象外です。見つからない場合は検索範囲も明示します。

Googleから取得した予定の件名・日時を表示し、回答読み上げが有効なら読み上げます。
今日・明日は日本時間の0時〜翌0時、今週は月曜0時〜翌月曜0時です。今日の終了済み予定や、今週の過ぎた日も含みます。
最初の連携対象は接続したアカウントの **メインカレンダー** のみです。共有・追加カレンダーは含みません。

終日予定、複数日にまたがる予定、繰り返し予定に対応し、キャンセル済み・自分が辞退した予定は除外します。
予定がなければその旨を表示します。通信や認証に失敗した場合はエラーを表示し、「予定なし」とは扱いません。
予定の作成・変更・削除は行いません。Googleへの問い合わせ方法は [Events: list公式仕様](https://developers.google.com/workspace/calendar/api/v3/reference/events/list) に従います。

1回の取得は最大5,000件まで、表示・読み上げは先頭50件です。50件を超えた場合は省略を明示します。
ネットワーク取得は取消可能で、取得中もタイマーの残り時間は進みます。会話中と同様、アラート再生は取得・読み上げ後まで保留します。

## 接続し直す・解除する

- JARVISの「接続を解除」で、このPCの認証トークンを削除し、Google側の権限取消も試みます。クライアント設定は再接続のため保持します。
- 通信できずGoogle側の権限取消に失敗した場合は画面に案内します。[Googleアカウントの接続一覧](https://myaccount.google.com/connections) でJARVISのアクセスを解除できます。
- 認証期限切れでは「接続を解除」→「Googleに接続」で許可し直してください。
- テスト公開中の外部アプリは、通常7日で更新用トークンが期限切れになります。これはGoogleの仕様です。[Google公式の有効期限説明](https://developers.google.com/identity/protocols/oauth2#expiration)
- `access_denied` はテストユーザー登録・アカウント選択を確認します。組織アカウントでは管理者の制限が影響することもあります。
- `redirect_uri_mismatch` やJSON読込エラーでは、クライアント種類が「デスクトップアプリ」であることを確認します。
- 取得権限のエラーではGoogle Calendar APIが有効か、読み取りを許可したかを確認します。

## 保存・通信と検証範囲

認証はシステムのブラウザーを使い、127.0.0.1の一時受付・ランダムstate・PKCEを使用します。[Googleのデスクトップ認証仕様](https://developers.google.com/identity/protocols/oauth2/native-app)
接続設定と更新用トークンは `%APPDATA%\jarvis-local\google-calendar.enc` にWindowsの保護機構で暗号化して保存します。平文保存へのフォールバックはしません。[Electron safeStorage仕様](https://www.electronjs.org/docs/latest/api/safe-storage)
元のダウンロードJSONは利用者の指定場所に残ります。暗号化ファイルや認証JSONはGit対象外です。

Googleへ送るのは認証情報と対象期間などのAPIパラメーターです。話した音声・質問文・会話履歴は送りません。
取得した予定は画面と読み上げに使い、診断ログ・会話履歴・Ollamaには渡しません。「さっきの予定を要約して」のような会話履歴を使う追加質問には未対応です。

自動テスト66件成功。日付境界、ページ送り、終日・日またぎ、キャンセル・辞退、OAuthのstate/PKCE、拒否・取消・タイムアウト、暗号化保存、失効時のエラー、権限不足、接続解除を含みます。
入力拡張後は69件成功。月末・年末・うるう年、曜日・日付・日数指定、次の予定の進行中除外・同時刻の複数予定・ページ境界を追加検証しました。証跡は `validation/calendar-extended-tests.txt`。
同梱版は合成APIデータで今日・明日・今週の表示、未接続案内、取得取消、タイマーとの非競合、実際のWindows暗号化保存、ログ・会話履歴への予定非記録を確認しました。
証跡: `validation/calendar-node-tests.txt`、`validation/calendar/packaged.json`、`validation/calendar/preview.png`。
既存のマイク受付・取消・復旧・ロック復帰・単一起動・子プロセス終了と、反復アラート・停止・消音・音声処理との非競合も同梱版で確認しました。証跡は `validation/calendar/desktop-regression.txt`、`validation/calendar/timer-regression.txt`。
