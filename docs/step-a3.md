# Step A-3 — ローカルAIの回答生成

実装日: 2026-10-09。ユーザーが選択したローカル方式で、一問一答の回答表示を追加。
質問入力・文字起こしの本人発声による評価は、引き続き後日実施する。

## 使い方（cmd）

このPCではOllamaを確認し、回答用モデルを取得済み。いつもどおり起動する。

```bat
cd /d D:\Jarvis
start-jarvis.cmd
```

- 声を使わない場合: 「文字で質問する」に入力して「質問する」を押す。マイク監視は停止のままで利用できる。
- 音声の場合: 呼びかけ→質問入力→文字起こし→AI回答→待機の順に進む。
- 「処理を取り消す」で入力・文字起こし・回答待ちを中断。「監視を停止」でも処理を中断し、停止設定を維持する。
- 「内容を消去」で質問・回答を消す。次の質問、ロック・スリープ、アプリ終了でも前の内容を破棄する。
- 今回は一問一答。前の質問内容をモデルに渡さない。回答の読み上げ・PC操作・予定参照・Web検索は未実装。

Ollamaに接続できないと表示された場合、WindowsのスタートメニューからOllamaを起動し、質問し直す。
モデル欠落の場合は、Ollamaを起動して次を実行する（モデル取得時のみインターネットが必要）。

```bat
cd /d D:\Jarvis
setup-local-ai.cmd
```

別PCではOllamaのインストールとモデル取得が必要。JARVISの同梱フォルダーにはLLMモデルを含めていない。
この変更でJARVISやOllamaのWindows自動起動設定は変更していない。

## 構成

- このPCの既存Ollama 0.40.1を使用し、モデルは `qwen2.5:7b`（約4.7 GB）。
- メインプロセスから `127.0.0.1:11434` にだけ接続。接続先をUIで変更できず、HTTPリダイレクトにも追従しない。
- 質問を渡す前にモデル情報を確認し、クラウドモデルやローカルGGUFと確認できないものは拒否する。
- 質問文だけをローカルOllamaへ渡す。マイク音声は渡さず、クラウドAPIへのフォールバックはしない。
- Ollamaへの会話リクエストはシステム指示と今回の質問のみ。ツールやOS操作権限は渡さない。
- 質問は最大2,000文字、コンテキスト8,192トークン、回答生成は最大384トークン。
  回答が上限で切れた場合はその旨を表示。上限到達は正常な回答完了と区別する。
- 接続・モデル確認は10秒、回答通信は90秒、回答処理全体は100秒で打ち切る。
- 取消・監視停止・ロック・スリープ・終了で通信を中断し、古い回答は表示しない。
- 接続不能・モデル欠落・不正な応答では理由を表示し、監視設定に応じて待機または停止へ戻る。
  AIの失敗をマイクワーカーの故障として扱わない。
- `keep_alive: 0` により回答完了後のモデル解放をOllamaに要求する。Ollamaアプリ自体は終了させない。
- 質問・回答はJARVISの設定や診断ログに保存しない。Ollamaは別アプリとして動作する。

## 検証

- Node自動テスト29件成功。ローカルモデル判定、質問の上限、空回答・長さ上限、二重開始、
  取消後の遅延回答、応答しない処理の時間切れ、エラー文からの内容漏えい抑止、停止設定の維持を含む。
- 実モデルに日本語の検証用質問「2足す3はいくつですか？」を渡し「5です。」を取得。
  モデル確認と通信を含め約2.99秒（1試行の実測であり、速度・正確性の保証ではない）。
- 同梱版でも文字質問→回答表示、内容消去、生成中取消、マイク停止設定の維持、
  質問・回答がJARVISの診断ログに記録されないことを確認。
- 同梱版の既存機能回帰試験も成功。入力取消・停止、復旧、ロックイベント注入、単一起動、親終了時の子終了を確認。
- 証跡: `validation/step-a3/local-answer.json`、`packaged.json`、`model.json`、`preview.png`、`regression.txt`。
- 本人発声による音声→回答の一連の操作、回答精度の体系的評価、AI回答を含む長時間動作は未検証。
- 小型モデルのため誤答や表記の不自然さがあり得る。最新情報や個人の予定を知っているとは扱わない。
