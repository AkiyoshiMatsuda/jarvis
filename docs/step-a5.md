# Step A-5 — 会話の継続とリセット

実装日: 2026-10-09。文字入力・音声入力の両方で直前の会話をローカルAIへ渡す。

## 試し方（cmd、文字入力だけで検証可能）

```bat
cd /d D:\Jarvis
start-jarvis.cmd
```

1. 「文字で質問する」に「私の好きな果物はマンゴーです。覚えてください。」と入力する。
2. 回答が終わったら「私の好きな果物は何ですか？」と続ける。
3. 「現在の会話」の「引き継ぐ会話を見る」でAIへ渡す履歴を確認できる。
4. 話題を変えるときは「新しい会話」を押す。生成・読み上げ中でも処理を止めて履歴を消去する。

文字入力ではマイクの開始は不要。「会話をすべて消去」も質問・回答・履歴をまとめて消す。
音声で続ける場合は、監視中に「続けて話す」を押すと固定の挨拶を省いて質問受付へ進む。
再度「Hey Jarvis」と呼びかけた場合も同じ会話の履歴を引き継ぐ。
読み上げ直後に自動で質問受付を開始する仕様ではない。画面が「質問を聞いています」になってから話す。
追加質問が無音の場合は5秒で受付を終了し、呼びかけ待ちへ戻る。過去の会話はそのまま保持する。
通常の最大15秒の録音受付・文字起こし・取消の上限は従来どおり。

## 保持と消去のルール

- 最新の成功した6往復まで、質問と回答を合計3,000文字までメモリ内に保持する。
  上限を超えたら古い往復から削除して画面に案内する。単独で上限を超える往復は保持できない。
- 失敗・生成途中の取消・生成上限で途切れた回答は履歴に追加しない。
  読み上げだけを止めた場合は生成済みの回答を保持する。
- 待機状態で10分経過すると履歴と質問・回答表示を消去する。
  質問受付・回答生成・読み上げ中はこの待機タイマーを止める。
- 新しい会話、全消去、Windowsロック・スリープ、アプリ終了で履歴を消去する。
  ロックから戻っても過去の履歴は復元しない。×でトレイへ隠すだけでは終了しない。
- 質問・回答・履歴はJARVISの設定や診断ログへ保存しない。
  Ollamaへは従来どおりこのPCの `127.0.0.1` にだけ送る。Ollama自体は別アプリ。
- 再起動やリセットで保持は終わる。長期記憶、Web検索、PC操作は未実装。

## 検証

自動テスト41件成功。履歴の順序・上限・ロール制限、取消・リセット後の遅延回答破棄、
失敗時と途中回答の除外、待機タイムアウト、追加の音声入力時の挨拶省略を検証した。
同梱版の実モデルでも「好きな果物はマンゴー」と伝えた後、「私の好きな果物は何ですか？」に
マンゴーと回答することを確認した。画面の履歴表示、生成中のリセット、ロック時の消去、
短縮したタイマーによる待機時間切れ、履歴が設定・診断ログに残らないことを確認した。
読み上げの完了・停止・消音・ロック時の中断とAI回答からの読み上げも回帰試験に成功した。
証跡は `validation/step-a5/packaged.json`、`preview.png`。
既存のマイク開始・停止、質問入力取消、ワーカー復旧、ロック・復帰、二重起動防止、
親終了時のワーカー終了も同梱版で成功した。結果は `validation/step-a5/regression.txt`。
本人発声による追加質問の認識精度、長い会話での回答品質、長時間耐久試験は未検証。
ローカルモデルの回答は誤ることがあり、履歴に含まれる情報を必ず正確に取り出せる保証はない。
