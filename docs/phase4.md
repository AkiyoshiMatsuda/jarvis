# Phase 4 — 日常利用への安定化

実装日: 2026-10-09（日本時間）。実機での長時間受け入れ評価は別途実施する。

## 今回の機能

- 同梱版の画面に「Windowsログイン時に自動起動」を追加。初期値は無効。
  オンにした場合のみ `JARVIS Local` のログイン項目を登録する。
  自動起動ではトレイで開始し、保存された監視設定に従う。
  オフにするとこのアプリのログイン項目を解除する。
- 登録後の実行ファイル移動には追従しない。移動前にオフにし、移動先でオンにする。
- マイク切断・ワーカー異常・応答停止では1、2、4、8、16秒後に最大5回自動再試行。
  各待ち時間は失敗後からの時間で、ワーカー起動・終了時間は別途必要。
- 同じ名前・ホストAPIのマイクだけに再接続。他のマイクへ自動変更しない。
- モデル欠落・不正設定・識別可能な権限拒否等は再試行せずERROR。
  判別できないドライバー障害も回数上限で停止する。
- 60秒の安定稼働後に失敗回数をリセット。停止・ロック・スリープで予約を取り消す。
- 上限到達後は「再試行」で明示的にやり直す。マイクを変更する場合は先に監視停止。
- 復帰・ロック解除時は条件を再確認してワーカーを再初期化する。
  ロックしたままの復帰や、停止設定での復帰では監視を開始しない。

## 検証範囲

`npm test` に復旧回数上限、重複障害の集約、処理中断、安定稼働後のリセット、
旧設定の互換性、自動起動APIの登録内容と読み戻し確認のテストを追加。
自動起動APIのテストは模擬APIで行い、この作業でユーザーのログイン設定を変更しない。

同梱版の統合テストでは実ワーカーを強制終了して自動復旧を確認し、
復旧待ちでの停止と、ロック・スリープイベント注入時の設定維持を確認する。
OSイベント注入は実際の画面ロックやスリープ試験の代わりではない。
