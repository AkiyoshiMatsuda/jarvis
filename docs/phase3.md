# Phase 3 — 画面表示と固定音声応答

実装・検証日: 2026-10-09（日本時間）。

検出時にACTIVATEDへ移行し、画面を表示して「はい、何でしょう？」と応答する。
応答中はマイクを解放し、音声の再生終了から700 ms後に入力と推論履歴を初期化して待機へ戻る。
停止・ロック・スリープ・終了・子の障害は応答を中断し、古い完了通知から監視を再開しない。

## 音声と表示

- `ui/public/response.wav` はWindows System.Speech / Microsoft Haruka Desktopで生成した固定応答。
  ユーザーの録音ではない。生成時の情報とSHA-256は `response.json` に記録。
- 通常起動時に音声合成プロセスや外部サービスは利用せず、同梱音声をローカル再生。
- 再生成する場合はcmdで `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\make-response.ps1`。
  日本語のWindows音声が必要。生成後は `npm run package` で同梱版を更新する。
- `showInactive()` による表示と、フォーカスがない場合のタスクバー点滅を使用。
  ユーザーがトレイから明示的に開くときのみフォーカスを移す。
- 応答音量は設定に保存。Phase 2の設定ファイルも読み込め、未設定時は80%。
- 音声エラーは案内を残して待機に戻る。完了通知が10秒以内に来なければ再生を止めて復帰。

## 検証

- `npm test`: 9件成功。再生失敗後の復帰、重複抑止、応答中の停止、再生タイムアウト、
  古い完了通知の無視、およびPhase 2の通信・設定・プロセステスト。
- 開発版の実マイク＋実音声再生で、ACTIVATED→LISTENING、応答中停止→PAUSEDを確認。
- `tests/check_desktop.py`: 同梱版でも音声再生開始・終了、重複抑止、待機への復帰、
  応答中停止、停止保存、閉じて常駐、二重起動防止、親強制終了後の子終了に成功。
- 統合テストは検出イベントを注入して応答経路を検証する。人の発声精度の測定ではない。
- ログの `detection_to_audio_event_ms` は親の検出受信からブラウザーの再生開始通知まで。
  `detection_to_display_request_ms` は表示要求まで。どちらも発話終了からの実遅延ではない。

## 手動確認が残る項目

1. トレイに隠した状態で本人が呼びかけ、画面表示と実際の聞こえ方を確認する。
2. 別アプリへの入力中・最大化・全画面で、表示とタスクバー点滅を確認する。
3. 発話終了→画面表示／実際の応答音開始の遅延を測り、Phase 1の基準と比較する。

これらの実環境評価は自動テストの成功と分けて扱い、未測定の性能を達成済みとはしない。
